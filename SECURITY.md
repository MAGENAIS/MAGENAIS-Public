# Security Policy

Security is a fundamental design principle of MAGENAIS.

The platform is developed with a security-first approach that emphasizes browser-native execution, user privacy, provider isolation, and secure integration with Artificial Intelligence services.

Protecting user data, credentials, workflows, and platform integrity remains a continuous priority throughout the lifecycle of the project.

---

# Responsible Vulnerability Disclosure

If you discover a security vulnerability in MAGENAIS, please report it privately.

Do not publicly disclose security issues until they have been reviewed and, where appropriate, addressed.

Responsible disclosure helps protect users and enables coordinated remediation.

When submitting a report, please include:

* MAGENAIS version
* Browser and version
* Operating system
* Steps to reproduce
* Expected behavior
* Actual behavior
* Screenshots or logs (if available)
* Proof-of-concept (if appropriate)

Clear and reproducible reports significantly improve investigation and response time.

# Security Architecture

MAGENAIS is designed as a browser-native Artificial Intelligence Operating System.

Whenever practical, processing occurs locally within the user's browser.

Core security principles include:

* Browser-First Execution
* Local-First Computing
* Provider Isolation
* Zero Trust Design
* Least Privilege
* Secure Provider Communication
* User Data Ownership
* Minimal Data Exposure
* Secure Credential Management

The platform architecture minimizes unnecessary transmission of user information while maximizing transparency and user control.

---

# API Key Security

MAGENAIS never includes API keys within the software distribution.

User-provided credentials remain under the user's control.

By default:

* API keys are stored only within the user's local browser storage.
* Credentials are transmitted only to the AI provider for which they were configured.
* MAGENAIS does not transmit API keys to GitHub or unrelated third-party services.
* Users remain responsible for protecting their own credentials.

Before sharing browser profiles, exported settings, or devices, users are encouraged to remove stored credentials.

---

# Browser Security

MAGENAIS relies on modern browser security technologies.

Supported browser protections include, where available:

* HTTPS
* Same-Origin Policy
* Content Security Policy (CSP)
* Secure Storage APIs
* Sandboxed Execution
* Cross-Origin Protections
* WebAssembly Security
* Browser Permission Controls

Security capabilities may vary depending on the browser and operating system.

---

# Privacy

MAGENAIS is designed to maximize user privacy.

Whenever technically practical:

* User data remains under user control.
* Local processing is preferred.
* Cloud communication occurs only when required by selected providers or user actions.
* Users determine which AI services receive their requests.

Privacy remains a core architectural objective.

# Third-Party Services

MAGENAIS integrates with external Artificial Intelligence providers.

Each provider operates under its own security, privacy, licensing, and terms of service.

Users should review the policies of any third-party services they choose to use.

MAGENAIS cannot guarantee the security practices of external providers.

# Security Best Practices

Users are encouraged to:

* Use trusted AI providers.
* Protect API credentials.
* Keep browsers up to date.
* Install platform updates.
* Verify provider endpoints.
* Avoid sharing sensitive credentials.
* Review browser permissions periodically.
* Report suspected vulnerabilities responsibly.

Security is a shared responsibility between the platform and its users.
